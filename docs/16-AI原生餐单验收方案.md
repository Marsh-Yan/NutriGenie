| A06 | 一日蛋白明显低于目标、日均接近目标 | 结果不得标为完全达标；逐日偏差可见，必要时修复或失败 | 校验单测、结果 API |
| A07 | 调味料价格缺失 | 成本覆盖率和未知项可见；不得声称总采购金额精确且预算已满足 | 目录单测、结果 API |
| A08 | 1 天 3 餐有合格备用候选时替换午餐 | 仅午餐改变，版本增加；无合格候选时返回具体拒绝原因 | 版本 diff、API 测试 |
| A09 | 午餐标记已吃，随后修改午餐或恢复旧版本 | 旧执行记录不被误解释为新菜已吃；已吃餐次编辑需明确处理 | 执行记录、版本对照 |
| A10 | 旧 MySQL 缺 `meal_plans.title` 等列 | 启动或迁移检查给出明确错误；执行迁移后创建成功 | 迁移演练、建表检查 |

## 4. 营养与可执行性人工复核

对每次真实模型样本抽查至少 3 天及全部触发修复的菜谱，检查：食材名称与步骤一致、离散食材数量可操作、单餐量合理、调味料没有随热量无限放大、烹饪时间与步骤相称、过敏和特殊饮食没有遗漏。逐日核对热量、蛋白质、脂肪、碳水、膳食纤维以及可获得的食盐/钠数据。缺少完整钠数据时只报告“未校验”，不得写“低盐达标”。

营养阈值应与产品面向人群和专业审核结论共同确定。当前验收只要求系统准确表达“达标、偏离、无法评估”，并证明总平均不会掩盖明显的单日偏差。

## 5. 发布门槛与记录格式

所有 P0 自动化场景通过；旧库迁移演练通过；真实模型运行无过敏和忌口漏检；失败任务可重试且不覆盖上一成功版本；异常无密钥或完整敏感画像泄漏。模型成功率、输出截断率、修复次数、成本覆盖率和逐日营养偏差须在验收记录中给出实测分布，再由产品负责人确定可接受阈值。

每个验收案例记录：案例编号、输入、环境、预期、实际、证据路径或版本 ID、结论、遗留问题及复测日期。未实施的阶段标记“未验收”，不能以文档中的预期替代通过结论。
