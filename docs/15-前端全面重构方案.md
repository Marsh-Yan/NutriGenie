# NutriGenie 前端全面重构方案

## 1. 目标与边界

以用户提供的 Awesomic 视觉参考重建 NutriGenie 全站：浅锌灰画布、白色卡片、近黑文字及主按钮、细线边框、少量橙色提示、圆角几何和真实食物摄影。旧版绿色系、渐变与装饰图形退出主要视觉。应用仍是中文营养规划产品，参考资料中的营销术语、虚构数据和 YC 标识不进入产品。

范围包括全部公开页面、登录注册、用户工作台、菜谱、计划、健康画像和管理后台，以及桌面、平板、手机布局。后端 API、数据结构、认证与权限、业务计算、持久化规则保持兼容；必要时只调整前端展示层和适配层。现有未提交的用户文件不清理、不覆盖。

## 2. 现状与依赖

- 技术栈：Vue 3、TypeScript、Vite、Vue Router、Pinia、Element Plus、SCSS、ECharts。
- `frontend/src/api` 封装 `/api/v1`、Bearer Token、错误信息和计划结果归一化。页面不直接拼接新接口。
- 路由有公开页、需登录页与管理员页；登录后带 `redirect` 回跳。
- 计划生成由 Pinia 轮询状态，包含超时、失败重试、结果延迟同步、对话修改、历史版本恢复。
- 餐食执行记录与服务端同步，旧本地状态可迁移；购物勾选、食材储备及部分偏好属于设备本地状态。界面必须如实说明各自保存范围。
- 管理端包含食材、菜谱、知识文档编辑、上传、重建与索引状态。操作反馈、危险操作确认均需保留。

## 3. 设计系统

| 角色 | 色值 | 用途 |
|---|---|---|
| canvas | `#f4f4f5` | 页面底色 |
| surface | `#ffffff` | 内容卡片和表单 |
| ink | `#09090b` | 标题、主按钮 |
| body | `#18181b` | 正文 |
| muted | `#52525b` | 次要信息 |
| border | `#ececee` | 细线分隔 |
| orange | `#ff5a00` | 少量高亮标签、关键状态 |

错误、警告、成功仍需有可识别的语义反馈，但以文案与图标共同表达，不仅依赖颜色。标题使用 DM Sans 与中文系统字体回退，正文使用相同字体栈。Cosmica 字体文件未提供，不假定其可用。正文以 15–16px 为主，表单不低于 14px；大标题使用响应式 40–64px。根据宽屏预览反馈，页面容器最大宽度调整为 1680px，正文段落继续限制行长；桌面大区块间隔约 80px，手机按视口缩减。大内容卡圆角 36px，按钮及输入 14px，标签 12px。卡片以 1px 边框分层，不使用常规投影。

交互统一为近黑主操作、白底次操作、清楚的禁用/加载/错误状态。键盘焦点可见；跳转主内容、移动端操作热区、减少动效模式和表单标签均保留。

## 4. 图片与文案

优化后的图片位于 `frontend/src/assets/editorial/`：`meal-bowl.webp` 用于首页主视觉，`avocado.jpg`、`fruit.jpg`、`breakfast.jpg`、`adjustment-food.webp`、`final-banner.webp` 用于步骤卡片、登录页、规划入口和底部横幅。它们是宣传图片，不作为数据库中具体菜谱的照片，也不暗示方案实际生成了图中食物。图片按页面裁切和响应式比例呈现，保留可读的标题区域；非首屏图片延迟加载。所有统计数字必须来自真实接口或明确写为“示例”。

## 5. 页面结构与功能对照

| 页面 | 重构后的布局 | 必须保留的行为 |
|---|---|---|
| 首页 `/` | 大标题、真实食物照片、三个直接入口和产品步骤 | 进入注册/创建、示例、菜谱、目标预填 |
| 示例 `/demo` | 编辑式方案预览 | 示例浏览与创建入口，不冒充用户数据 |
| 登录 `/auth` | 摄影侧栏与简洁表单 | 登录、注册、校验、错误提示、回跳 |
| 今日 `/dashboard` | 当前方案、今日三餐、执行及采购摘要 | 当前方案恢复、状态同步、跳转 |
| 画像 `/profile` | 分步表单和摘要 | 加载、字段校验、创建/更新 |
| 创建 `/plan/new` | 需求输入、模板、食材、预算周期 | 草稿、画像前置、提交、失败恢复 |
| 工作台 `/plan/:id` | 今日/整周/采购/分析标签 | 轮询、重试、结果、执行、对话、换餐、版本、打印 |
| 方案历史 `/plans` | 紧凑列表与筛选 | 分页、归档、改名、复制、恢复打开 |
| 菜谱 `/recipes` 与详情 | 图文目录和详情 | 搜索筛选、详情、收藏/来源及返回逻辑 |
| 管理 `/admin` | 数据概览 | 权限与数据加载 |
| 食材、菜谱管理 | 桌面表格、移动卡片 | 查询、新增、编辑、删除确认 |
| 知识库管理 | 文档列表、编辑区、任务状态 | 上传、保存、删除、重建、索引/重试 |
| 404 | 简明恢复入口 | 返回首页或工作台 |

管理端使用同一视觉系统，但信息密度高于首页，不照搬摄影式营销布局。

## 6. 实施顺序

1. 固化路由、API、状态和本地存储契约，建立页面功能清单。
2. 重建设计变量、全局样式、导航、页脚、按钮、卡片、状态组件；避免旧绿色残留。
3. 重做首页、登录和创建入口的布局与摄影使用。
4. 改造用户核心流程：画像、今日、计划工作台、历史、菜谱与详情。
5. 改造管理端，并核对所有移动端编辑和危险操作入口。
6. 运行前端类型检查、构建、现有测试；在可用环境下进行关键链路的手工浏览与后端联调。记录无法验证的外部依赖，不将静态检查称为端到端通过。

## 7. 验收标准

- 所有既有路由可访问，权限拦截和登录回跳正确，链接无死路。
- 公开页和工作台在 375px、768px、桌面宽度无横向溢出；键盘可完成主要操作。
- 画像到创建、生成中到完成/失败、对话修改、版本恢复、执行同步、购物勾选、方案历史和管理 CRUD 保持可用。
- 请求方法、路径、参数、响应适配与现有后端契约一致；不以演示内容替代真实数据。
- `npm run build` 与 `npm test` 通过；关键手工场景及限制记录在交付说明中。

### 关键接口与状态契约

| 业务流程 | 前端入口 | 后端接口或存储 | 成功与异常验收 |
|---|---|---|---|
| 登录与注册 | `/auth` | `/api/v1/auth/register`、`login`、`me`；Bearer Token | 登录回跳，401/校验错误可读，退出清空用户内存状态 |
| 健康画像 | `/profile` | `/api/v1/profiles/me`、`profiles`、`profiles/id/:id` | 首次创建、再次编辑、加载错误和字段错误均可处理 |
| 创建方案 | `/plan/new` | `POST /api/v1/plans` | 画像缺失先补画像；文本、周期、预算与已有食材正确提交；失败可重试 |
| 生成与调整 | `/plan/:id` | `GET /plans/:id/status`、`GET /plans/:id`、`POST /messages`、`POST /retry` | 进度、超时、失败、结果延迟、调整后的新结果都可恢复 |
| 历史版本 | `/plan/:id` | `GET /messages`、`GET /versions`、`POST /versions/:id/restore` | 版本列表及恢复后内容同步刷新 |
| 餐食执行 | `/dashboard`、`/plan/:id` | `GET/PUT /plans/:id/execution`、`POST /execution/import` | 服务端状态优先；旧本地记录只导入缺失项 |
| 采购与偏好 | `/plan/:id`、`/plan/new` | 用户及方案隔离的本地存储 | 刷新后保留，换账号/方案不串数据，明确提示仅本设备保存 |
| 方案历史 | `/plans` | `GET/PATCH /plans`、`POST /plans/:id/clone` | 分页、归档、改名、复制、打开原方案 |
| 菜谱 | `/recipes`、`/recipes/:id` | `GET /recipes`、`GET /recipes/:id` | 筛选分页、详情、来源和返回路径 |
| 管理端 | `/admin/*` | `/admin/overview`、`/admin/ingredients`、`/admin/recipes`、`/admin/knowledge/*` | 管理权限、增删改、上传及索引任务状态；手机端操作按钮可见 |

接口路径在表中省略重复的 `/api/v1` 前缀。计划响应继续经过 `planResultAdapter` 归一化，不能直接依赖单一版本的数据结构。

### 视觉与交互检查

- 首页、登录、示例、创建及核心工作台在宽屏和窄屏都有清楚的第一操作；无固定宽度造成的横向滚动。
- 每种异步流程有加载、成功、空结果、失败或重试状态；焦点、标签、危险操作确认和减少动效行为可用。
- 食物摄影只出现在编辑展示区域；真实菜谱没有图片时显示中性文本卡，不复用无关照片。

## 8. 已知风险和处理

- 参考文档是营销站的视觉描述而非每页设计稿；复杂业务页以信息可读、操作完整为优先。
- 菜谱缺图时采用中性占位与文本，不错误复用宣传图片。
- DM Sans 若无法本地提供，则浏览器回退到系统字体，不依赖运行时外链。
- 现有测试覆盖有限。构建与测试可证明类型和部分行为，但完整接口正确性需要运行中的后端和可用测试数据。
