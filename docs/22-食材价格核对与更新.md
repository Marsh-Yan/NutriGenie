# 食材价格核对与更新（2026-11-01）

本次目标为本机 `nutrigenie.ingredients` 的价格补充，同时同步种子数据。小程序独立库的认证尚未配置完成，本次没有将旧库冒充为小程序数据库，也没有发布不符合其可食部口径的价格。

## 来源与口径

- 来源：[上海市发改委 2026-10-29 主要主副食品品种价格信息表](https://fgw.sh.gov.cn/fgw_jgjgdt/20261029/1ed9b3d2cf614b5db697b302cc118d68.html)，上海市价格监测与成本调查队提供。
- 采用附件中的农贸市场、超市监测点**均价**，不是批发价，也不是全国统一售价。采价日为 2026-10-29。
- 原始 XLS 保留于 `backend/app/db/seed_data/reference/shanghai-prices-20261029.xls`，SHA256 为 `3e828ef1a92d3d5b1e73621e7c22d85dcaa1f4ed8200ec53c8c90e605e4a9f86`。
- 33 项匹配、原始小数、规格、列位置、链接及日期在 `backend/app/db/seed_data/market_prices_20261029.json`。选用某个品种作为通用品名参考的情况在 `mapping_note` 中说明。
- 所有本次写入的报价均为 **人民币元/斤（500 克）**，价格和 `unit` 一起改。比如番茄 4.316271 元/500克，存为 4.32 元/斤，250 克对应 2.16 元。不能把 4.32 写到“个”或“g”单位上。
- 原表均价按十进制四舍五入至分。原字段为 `DECIMAL(8,2)`，因此不存每克小数以免截断。有效期是应用维护策略（截至 2026-11-28），不是官方保价承诺。

## 覆盖范围与限制

132 项食材中，本批核对 33 项，其余 99 项保留原值并明确列为未核对，不能声称全库已经是最新行情。缺价不代表免费。

包括番茄、青椒、西兰花、大蒜、生姜、大米、黄瓜、土豆、胡萝卜、洋葱、生菜、菠菜、空心菜、牛腩、鲜蘑菇、茄子、西葫芦、菜花、卷心菜、芹菜、韭菜、冬瓜、猪瘦肉、肋排、鸡蛋、活鲫鱼及六类水果、面粉。

未用整鸡价格替代鸡胸肉、活虾价格替代虾仁、青椒替代彩椒，也未将 5 升食用油当成 5 千克。牛奶、油、调料、豆腐及包装食品需要确切品种与净含量后再补；目前旧库中这些记录的零值或旧价仍有局限。

**购买重量与可食部净重不同。** 带壳蛋、活鱼、带骨肋排及带皮水果价格保留采购口径，没有编造出成率。旧系统菜谱中“个、根、颗”仍通过既有近似重量估价；本次没有把它们转换成精确克重。只有实际称重、同一采购状态的重量才能按比例准确计算。小程序需要可食部价格证明，本批不能直接写入其 `price_per_100g` 并宣称预算完整。

## 更新与回滚

维护工具：`backend/scripts/update_market_prices.py`，应用服务器不需要 Excel 依赖。离线维护时额外安装 `backend/scripts/requirements-market-prices.txt`。工具逐项校验附件 SHA、采价日期、品种、规格、单位、原始报价、重量与四舍五入结果；默认仅预览。

```powershell
python backend/scripts/test_market_prices.py
python backend/scripts/update_market_prices.py --file backend/app/db/seed_data/market_prices_20261029.json --as-of 2026-11-01
python backend/scripts/update_market_prices.py --file backend/app/db/seed_data/market_prices_20261029.json --as-of 2026-11-01 --apply
```

应用前持有行锁、校验食材编号及名称，并备份到忽略目录 `backend/.local-backups/market-prices-<时间>/`：全库食材价格快照 `before.json`、原始种子文件 `ingredients.json`、报价证据 `source.json`、变更明细 `report.json`、条件回滚 `restore.sql`。只更新 `ingredients.unit/unit_price`，不修改菜谱用量、营养、账号或历史方案。

数据库提交前异常会回滚并恢复种子文件；数据库与文件系统无法实现跨系统原子提交，若进程意外中断，按备份核对二者状态。回滚 SQL 仅在记录仍为本次新价格与单位时恢复旧值，避免覆盖后续价格；执行时应核对受影响行数。种子文件回滚使用同目录备份，合并后来改动后再恢复。
