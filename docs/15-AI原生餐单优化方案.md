# AI 原生餐单生成与执行优化方案

日期：2026-09-23。依据当前代码和真实模型、接口实测制定。本文是后续实施依据，不替代健康专业人员对个体饮食的评估。

## 1. 目标与边界

用户从画像和自然语言需求出发，得到可解释、可烹饪、可采购的餐单；修改、换餐和执行记录保持一致。系统必须区分“结构有效”“营养目标达成”“成本可信”和“用户已实际执行”，不能用一个 `completed` 掩盖关键偏差。

保留现有基本分工：模型设计菜谱，标准食材目录核算营养与成本，后端编排和校验，版本保存结果。食物过敏与预算等约束不能仅靠提示词维持。

## 3. 目标数据契约

### 3.1 需求与约束

建立唯一的有效需求快照：画像基础值、首次明确要求、每次编辑增量，按时间顺序合成。显式预算接受“预算200”“预算200元”“总预算改为200元”等形式；冲突时最新明确要求优先。修改过敏或忌口时进行结构化增删，未提到的限制保留。天数只接受服务端实际支持的 1–7 天，超范围在启动模型前反馈。

对话动作应区分全周重做、单日调整、单餐替换、约束变更。单餐修改默认固定其余餐次；若无法满足硬约束，返回具体原因和可选的扩大修改范围，不默默改动其他餐次。

### 3.2 候选与版本

保存已使用菜谱和合格备用候选，保留稳定菜谱键和来源。换餐先从备用池选择，重新验证整周营养、预算、重复度及食材安全；无可选项时给出明确原因。版本应记录模型、提示词版本、目录版本、约束快照、成本覆盖率、修复次数、校验结果和候选来源。

执行记录至少与实际吃过的菜谱键和版本关联。已完成餐次默认不可被自动编辑；修改未来餐次后，只清除受到影响的采购勾选及待执行状态。恢复旧版本也需要检查当前是否存在运行任务，并提示执行数据是否对应。

### 3.3 营养、份量和成本

分别输出每餐、每日与整段计划的热量、蛋白质等核算值。日均值不能代替逐日校验。将“硬约束失败”“目标偏离但可展示”“目录数据不足”分开返回，界面必须显示其含义。份量校准需约束离散食材、调味料和单餐总量；无法以合理份量达标时应重新组合菜谱或明确告知目标无法同时满足。

预算分为食材总成本、扣除有数量的库存后的采购成本及缺价格项。缺价格项不能按 0 元计入“预算已满足”的结论；应显示成本下界及覆盖率。过敏与特殊饮食以食材目录的结构化属性为主，步骤文本扫描只作补充。钠、食盐等当前目录没有完整数据时不得声称已做充分控制。

## 4. 实施顺序

| 阶段 | 工作 | 交付判定 |
| --- | --- | --- |
| P0a | 部署前数据库迁移检查；明确预算/天数解析；修复编辑时的快照覆盖 | 真实输入与编辑得到一致的有效约束；旧库明确报迁移缺失 |
| P0b | 模型输出限额时缩减候选并重试一次；记录截断类型；控制候选量和提示长度 | 输出超限不直接终止首次请求；重试仍失败时返回可识别错误 |
| P0c | 逐日营养偏差、成本覆盖率、可执行份量检查 | 最终结果不再把关键目标偏差标为无条件通过 |
| P0d | 保存备用候选并让换餐可用；执行状态关联版本/菜谱 | 1 天 3 餐存在合格备用时可换，已完成状态不会错误继承 |
| P1 | 局部编辑、餐次覆盖范围、过敏结构化目录、持久任务队列 | 相关验收场景通过，不依赖模型“自觉”遵守 |
| P2 | 有数量库存、缺价治理、反馈闭环、RAG 质量评测 | 采购与执行数据可追溯，个性化有可撤销来源 |

每阶段先做确定性验证，再在隔离数据库对真实模型做固定输入复测。真实模型有随机性，须记录成功率、耗时、修复率、输出截断率和各项偏差分布；单次成功不足以作为上线验收。

## 5. 发布与回滚

数据库迁移先在备份副本验证，再部署代码；服务启动时检查必要列，不应依赖 `create_all` 更新旧表。新版结果字段保持向后兼容，旧版本没有备用池时换餐应给出可理解的不可用原因。发生生成失败时保留上一成功版本及执行数据。记录结构化失败类型与模型用量，避免日志中暴露用户隐私和密钥。

## 6. 首轮实施进度（2026-09-23）

已开始实施 P0：修正预算和天数的显式解析、编辑约束继承及旧任务写回保护；增加 1–7 天的入口校验和旧数据库缺列提示；模型输出截断后以较少候选重试；按预计份量选菜并跨天平衡蛋白质，逐日检查热量和蛋白质；保存备用候选供换餐，保持未替换菜谱键；将缺价采购金额标为下界，并禁止直接替换已完成餐次。相关代码和测试已提交到工作区，尚未部署。

本次真实模型隔离复测完成 7 天 21 餐，候选 27 道、使用 21 道，最终校验通过，耗时 84.5 秒；中途发生一次输出截断、两次过敏原修复。该结果证明当时路径可跑通，不构成稳定性发布结论。仍需完成 P0 的可执行份量限制、缺价预算的明确判定和旧 MySQL 迁移演练；P1/P2 尚未实施。

后续实施：执行状态已绑定菜谱键及记录时的版本；生成、换餐和恢复若改变餐次，会把旧执行状态移入历史表，当前餐次不继承旧“已吃”状态。增加迁移 `20260923_0007` 和历史查询接口。鸡蛋非整数份量及明显偏大的肉、油用量现在给出可执行性警告，仍需完善份量重编排与步骤同步。按产品当前范围，正式生成任务关闭 RAG 检索；RAG 功能与 A17 暂缓，不参与当前发布门槛。

关闭 RAG 后的三次隔离真实模型复测依次为：一次在 350 元预算下得到约 403.9 元而失败；一次因第 7 天热量及前两天蛋白不足失败；加入预计份量成本评分和整周营养、预算联合修整后，一次完成 7 天 21 餐，18 道不同菜，重复上限 2，日均 1998.2kcal，采购已知费用 312.89 元，耗时 75.5 秒。仍需扩大样本并治理输出截断与过敏原修复率，不能据此推断稳定成功率。

预算结果现在明确区分已知费用是否超支、缺价导致的无法判定，以及未设置预算；缺价采购额继续显示为下界。真实价格缺失的治理和预算覆盖率发布阈值仍待产品与数据验收。
